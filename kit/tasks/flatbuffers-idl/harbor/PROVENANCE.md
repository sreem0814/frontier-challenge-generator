# Provenance

## Source

FlatBuffers by Google, https://github.com/google/flatbuffers, release v25.12.19 (commit 7e163021e59cca4f8e1e35a7c828b5c6b7915953), Apache-2.0. The image fetches the source tarball of that commit (SHA-256 4236c5d2...4536) and checks the trimmed tree against a fixed hash.

## Extraction

The environment keeps the C++ headers, the `flatc` sources (driver, code generators, gRPC generators, reflection runtime, binary annotator), the CMake build, `reflection/reflection.fbs` and the top-level documentation pages. Removed: `tests/` (with its golden binaries, checked-in `.bfbs` files, expected outputs and the parser unit tests), every language runtime and port (Python, Rust, Go, Java, Kotlin, Swift, TypeScript, Dart, C#, PHP, Lua, Lobster, Nim), `goldens/`, `samples/`, `examples/`, `benchmarks/`, the gRPC examples and tests, scripts, packaging and the per-language documentation. `src/idl_parser.cpp` (4,574 lines upstream) is replaced by a stub that only satisfies the linker. `/app` is a fresh git repository with a single commit; no upstream history ships.

The reference solution is upstream's `src/idl_parser.cpp` at the same commit. The hidden set was generated by random schema, JSON, proto and schema-evolution generators plus upstream's own test schemas (from the removed `tests/` tree), run through `flatc` built from the reference with the same toolchain as the image; each case was run three times from different directories and kept only when the results agreed, and cases the stub would pass were dropped. The visible samples come from the same generators with a different seed, and no hidden input appears among them.

## Why it is real work

`idl_parser.cpp` is the front end every FlatBuffers user goes through: schema parsing, JSON conversion, binary schemas for reflection and schema evolution checks. Rewriting it to match the shipped compiler exactly is what a maintainer faces when porting the compiler, replacing its parser or reproducing its binary schema and data layout in another tool, where any difference in field layout, defaults or diagnostics breaks compatibility with existing users.
