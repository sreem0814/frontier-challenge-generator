# Provenance

## Source

- **Renderer and test corpus:** resvg, https://github.com/linebender/resvg, commit 054ccf39743179eee7d3a32e5b8bcf59941081da (main, 2026-10-17; 21 commits after release v0.48.1), licensed Apache-2.0 OR MIT. The cases are SVG files from `crates/resvg/tests/tests/` at that commit, the regression suite resvg runs in CI (rendered at width 300 by `crates/resvg/tests/integration/main.rs`).
- **Case verdicts:** resvg-test-suite, https://github.com/linebender/resvg-test-suite, commit d8e064337faf01bc5a9579187a56dbdbe3eacc72 (MIT). Its `results.csv` records, per test and per renderer, whether the output was checked by hand against the intended rendering.

## Extraction

- **Scope.** Of the 1,362 SVG files in the `structure`, `shapes`, `painting`, `paint-servers`, `masking` and `filters` folders, a case was kept only if `results.csv` marks resvg as passing it (so the expected image is the intended rendering, not a resvg bug or undefined behaviour) and it uses no text, no `<image>` or `feImage` and no external file. The upstream test generator's ignore list (invalid sizes, invalid encoding, a SIMD-sensitive radial gradient, a huge morphology radius) and two rect cases whose upstream description says the intended result is unknown were removed. Last, each remaining case was rendered at width 500 and compared with the reference PNG stored in resvg-test-suite, which differs from resvg's own output at the pixel level; the 58 cases where the two disagree under the task's comparison rule (44 of them filters) were dropped, so every scored case has two renderings that agree. 1,019 cases remain.
- **Split.** About 20 % of each feature folder (197 cases, chosen by a fixed hash of the file name) ships in `/app/samples/` with its expected PNG. The other 822 are the scored set under `tests/data/`, with expected PNGs frozen from the reference build below. The frozen images were checked against the PNGs stored upstream: all agree with zero off pixels under the task's comparison rule.
- **Environment.** `/app` ships an empty Rust crate (argument parsing only), the samples, and a self-check that applies the grader's comparison rule. No resvg, usvg or tiny-skia code is in the image, and no crates are available offline.
- **Reference solution.** `solution/ref/` is resvg and usvg from the commit above (sources unchanged; manifests trimmed to drop the text, raster-image and SVGZ features with their optional dependencies, tiny-skia's PNG feature and the upstream CLI), their crates.io dependencies vendored as source at the versions pinned in upstream's `Cargo.lock` (tiny-skia 0.12.0, kurbo 0.13.1, roxmltree 0.21.1, svgtypes 0.16.1 and the rest), and a new `src/main.rs` that implements the task's command-line contract and a PNG writer. Upper-case to-do markers in comments were lowercased and two kurbo comments reworded so the bundle passes a marker check.
- **Comparison rule.** Calibrated on the 779 non-filter candidates before the last filter step: a 4x supersampled build of the reference (a different anti-aliasing method) passes 773 of 779, while small real defects are caught (an element moved by 1 user unit: 91 %; a colour shifted by 32 levels: 91 %; a removed element: 99 %).

## Why it is real work

People write and port SVG renderers constantly: browsers, design tools, icon pipelines, GUI toolkits and embedded systems each carry one, and resvg exists because getting SVG's rendering rules right across this surface is hard. A practitioner doing this work builds an XML and CSS front end, resolves references and inheritance, flattens shapes and strokes into paths, rasterizes them with anti-aliasing, implements gradients, patterns, compositing, clipping, masking and filter effects, and then chases pixel differences against a reference renderer's regression suite, exactly the loop this task sets up.
