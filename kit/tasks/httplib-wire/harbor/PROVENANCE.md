# Provenance

**Source.** cpp-httplib by yhirose, https://github.com/yhirose/cpp-httplib, release v0.62.0 (commit 74ef3c42188acd6391f027c4337fb0e1a68c0024), MIT licence. The library is a single header, `httplib.h` (24,011 lines at this release), with its own GoogleTest suite in `test/test.cc`.

**Extraction.** `/app/httplib.h` is the release header with the bodies of 90 functions and of the `FormDataParser` class replaced by stubs (2,579 non-blank lines removed): request and status lines, header fields and their validation, Content-Length, chunked and close-delimited bodies in both directions, URL parsing and percent-encoding, query strings, multipart/form-data parsing and serialization, byte ranges, Accept and Accept-Encoding negotiation and conditional requests. Declarations and everything else are untouched. The image also ships the upstream README files, user guide and examples, but not `test/`, the fuzzers or the git history. The reference solution is the unmodified release header. The graded set has two parts: the upstream tests from `test/test.cc` that pass with the release and fail with the stubbed header (716, run one per process; the one libcurl test is dropped and the port-shard variable renamed so tests can run in parallel), and 14,044 generated cases (library calls, a client against a scripted peer, raw requests against a server) whose expected results were recorded from the release header, kept only when three reference runs agree and the stubbed header differs.

**Why it is real work.** Rebuilding an HTTP/1.1 message layer to match an existing implementation byte for byte is what a maintainer does when porting or hardening a widely embedded library: the RFC 9110/9112 rules, the security fixes accumulated in chunked and range handling, and the many edge cases of multipart and URL encoding all have to agree with what deployed clients and servers already depend on.
