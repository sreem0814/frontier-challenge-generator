# Provenance

**Source.** project-chip/connectedhomeip, release tag v1.6.1.0 (commit 3bcdd56ba54fb88b2afb4bfef575014671df7aa7), Apache-2.0, https://github.com/project-chip/connectedhomeip. Submodules used: third_party/nlassert and third_party/nlio at the commits pinned by that tag (Apache-2.0).

**Extraction.** The environment ships a trimmed tree: the sources needed to build the TLV codec (src/lib/core), message framing (src/transport/raw/MessageHeader), onboarding payload codecs (src/setup_payload) and the JSON<->TLV converter (src/lib/support/jsontlv), plus exactly the headers that build includes. The 21 implementation files of those components were replaced by stubs that keep every public signature; headers are unchanged. Unit tests, fuzzers, the Python and Kotlin TLV implementations and the rest of the SDK are not shipped, and the tree has no git history. Upstream's GN build was replaced by a small CMake file; a two-function platform shim (no-op log sink, /dev/urandom DRBG) stands in for the platform layer. Upstream to-do comment markers in the shipped headers were reworded to "Upstream note:"; no code changed. Protocols.cpp and AdditionalDataPayloadGenerator / OnboardingCodesUtil / SetupPayloadHelper were left out (they pull in crypto or platform configuration).

**Grading data.** Case scripts were generated by an independent Python generator (its own TLV encoder per the Matter specification Appendix A, QR and manual-code encoders per section 5.1, random writer programs, mutations and truncations, JSON documents in the jsontlv format) and run through a C++ driver linked against the upstream v1.6.1.0 sources. Each case's transcript was frozen; cases where upstream crashed, differed across three runs, or triggered AddressSanitizer/UBSan were dropped. The reference solution is the upstream implementation of the 21 files.

**Why it is real work.** Reimplementing a wire codec and its consumers byte-for-byte against an existing implementation, including every error path, is what porting or re-implementing the Matter stack for a new platform or language requires; interoperability depends on exact encodings and identical rejection of malformed input.
