RULES (from CLAUDE.md and the spec; restated because they matter most):
- Privacy: never contact, fetch, search for or name the platform that receives tasks, in any file, query or prompt. task.toml's [task] name is "cg/<slug>": "cg/" is the repo's placeholder prefix, which l0_check.py accepts and make_zip.sh replaces with the private prefix (from ~/.config/cgpipe/org) inside the zip only. Never write the real prefix into any file. No personal or account details in the bundle.
- Sealed grading: hidden cases, reference outputs and grader code never go into a web search, a fetched URL or anything under environment/.
- Downloaded code is read before it runs, and runs only with `python3 -I` or inside a throwaway container.
- No API keys or tokens in any file.
- No LLM-as-a-judge: scoring is by code only.
- The machine (VM1, 8 CPUs, 22 GB) is shared with the running idea pipeline and other build agents. Keep local Docker work light: build and run heavy images on your runner through kit/scripts/l3_run.sh (it uses CG_RUNNER_HOST), and never start more than one local Docker build at a time. Never stop or modify other containers, volumes or processes.
- The runner is shared too: never start work on a runner that reports DISK_LOW, and don't touch ~/tb-runs on vm3.

SCOPE (lesson from the first bundle):
- mjcf-dynamics scored 0.99 in its first frontier trial after 23 minutes of an 8-hour budget: too easy. Size the scope so a strong agent cannot finish it in a few hours. calamine-go then scored 1.0 in 41 minutes of its quarter probe: agents split a port across parallel subagents, so translating source that ships in the image is fast. rdp-codecs (seven FreeRDP codecs, bit-exact, no source shipped) then scored 1.0 in 44 minutes of a short probe: Opus with parallel subagents rebuilds well-documented, well-known formats in under an hour even when nothing can be copied. Scopes need hard, poorly documented behaviour that must be worked out against the oracle, not just volume. The spec's review gate accepts a task above the band only with a capability gap against a weaker model (Qwen class), so design for work a weaker model loses track of: several strategies that must work together, long dependency chains, measurement-driven tuning, no single lever. Some frontier trial must also generate a substantial amount of work (the long-horizon gate). Expected outputs must come from a real external oracle (upstream code, a conformance suite, real data), never from a model you write; for optimization and research the reference must be expert or upstream work, not your own (BUILD.md step 4). Do not ship the source the agent is meant to reproduce; let it work from a spec, docs, samples and the behaviour the hidden set checks. If the hidden set rewards a narrow core, widen the scope (more of the real surface, more buckets) before you report phase 1a. Some trial must still be able to reach 0.9 within the budget tier, so stay within what one excellent session at that tier can do.
