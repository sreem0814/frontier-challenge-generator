# BUILD: from a validated idea to a submitted bundle

How to turn a seed that the pipeline marked `validated` (README.md) into a task bundle that passes everything we can check locally. The spec, capture/instructions.md, is the single source of truth. Platform identifiers are private and live outside the repo: ~/.config/cgpipe/org holds the task-name prefix that l0_check.py enforces, and ~/.config/cgpipe/denylist.txt holds blocked names that l0_check.py and remote_run.sh add to scripts/leak-denylist.txt. Paths below (scripts/, tasks/) are relative to kit/.

Build agents get kit/agent-brief.txt (with the seed and runner filled in): the rules, where to work, what done means and where to stop. Each phase runs as a fresh agent that picks up from build/notes.txt, so no agent carries a long context: phase 1a (steps 1-3, Opus), phase 1b (steps 4-5, Opus), phase 2 (steps 6 and 8, Sonnet). Build agents run at medium effort. A rework round is a fresh phase-1a agent with the trial result, not a resumed one.

## 1. Research method (from /work/tb-ws PROTOCOL)
- Search order: capture/instructions.md first (it wins over everything), then Harbor's source (~/tb-clones/harbor), then the task's upstream project (repo, issues, release notes, conformance suite), then everything else.
- Follow citations only for questions that change a decision. Stop a thread after two rounds with no new facts, or after 8 rounds.
- Open every URL yourself and record its access date. Confirm important claims with two sources or mark them single-source. Record exact versions.
- Keep facts, inferences (marked INFERRED) and recommendations apart.
- Subagents: collector (haiku) fetches and extracts, analyst (sonnet) fills templates, judge (opus) decides. Each returns 10 lines or fewer plus file paths, and writes into data files or existing docs, never new markdown files.
- Checkpoint in README.md so /clear or /compact loses nothing.

## 2. Task folder
Copy tasks/_template/ to tasks/<task>/.
```
tasks/<task>/
  harbor/                  the bundle; the only part that ships (make_zip.sh) or reaches VM 3 (remote_run.sh)
    task.toml  instruction.md  PROVENANCE.md
    environment/           Dockerfile (spec tail verbatim), timer.sh (byte-equal to the spec), the system under /app
    tests/                 test.sh (harden, evidence), collect.py (build, gates, cases), compute_reward.py (3 files)
    solution/              solve.sh plus the reference source (>= 150 non-blank code lines)
  l3/                      drop-in replacements for harbor/solution/, run by l3_run.sh
    near-miss-*/           plausible wrong work: must score 0 for the intended reason
    partial-*/             real but incomplete work: must land strictly between 0 and the ceiling
    alt-solution-*/        a different correct solution: must reach the ceiling
    edge-inside-*/ edge-outside-*/   just inside / outside one tolerance (note the number and why in the first lines)
  spike/  runs/  build/    generated, git-ignored (copy the pipeline's data/spikes/<seed>/ into spike/ to start)
```
Write per-task decisions as dated lines in README.md, not in a new file.

## 3. Order of work
| Step | What | Done when |
|---|---|---|
| 1 | Re-read the seed's V1 report, judge notes and spike notes (data/seeds/<id>.json, data/spikes/<id>/SPIKE.md) | open questions listed in README.md |
| 2 | Environment: Dockerfile (pinned digest, toolchain, vendored deps, Node 22 + Claude Code, timer tail), the system under /app | image builds; L0 docker and leak groups clean |
| 3 | Verifier: test.sh, collect.py, compute_reward.py; hidden set generated and frozen under tests/. Then two zero-token files in build/: **core.json** `{"core_share": x, "core_buckets": [...], "why": "..."}`, the share of the reward a narrow solution would earn (what a strong agent builds in its first hour), computed from the verifier's weights and the frozen hidden set; and **targets.txt**, the /app-relative files the agent writes, most important first, with an optional `build: <command>` line. **Optimization** (spec line 49): the equivalence gate compares against the shipped baseline's own outputs, frozen, independent of the optimized path; timing is paired or alternating with warm-up and medians over fixed operation budgets (never valgrind or perf counters: gVisor), the noise margin *d* is measured on the runner, and reward = 2^u - 1. **Research** (line 55): a deliberately out-of-distribution hidden split, domain constraints and an authenticity audit of the deliverable (it was really produced in the run: provenance of the checkpoint or program, re-evaluation from scratch where cheap), reward normalized between the shipped baseline and the reference, and `reward_cap` declared | compute_reward.py gives the right reward on hand-made evidence files (nop, gate fail, partial, full); core_share below 0.5 (at or above: widen before any trial). Optimization: also the lever share, the part of u the single biggest kernel or change earns, below 0.5 (spec line 353: avoid one-lever tasks) |
| 3b | **Difficulty ladder, before the reference**, cheapest first; each rung runs only if the one before passed. A trial needs only the environment, the verifier with its frozen hidden set and a working-draft instruction.md (the full contract, not yet polished); before the ladder, `l3_run.sh <task> --only nop` scores 0. (1) **Recall check**: `bash scripts/recall_check.sh <task>`, one tool-less Sonnet call per target file writes its own implementation in one go from the instruction, the stub and what it knows (never upstream code verbatim), scored by the verifier on the runner; a few dollars, minutes. Only for interpreted languages (Python, Ruby, JavaScript), where partly right code earns partial credit: for compiled targets (C, C++, Rust, Go) one-shot code never built in three tries, so record `{"kind": "recall", "skipped": "compiled language"}` in build/gates.jsonl and go to the short probe. (2) **Short probe**: one frontier trial at a tenth of the budget, `bash scripts/remote_run.sh run <task> --keys claude --label probe10 -- -a claude-code -m anthropic/claude-opus-5-5 -k 1 -n 1 --allow-agent-host api.anthropic.com --agent-timeout-multiplier 0.1`. (3) **Quarter probe** (`--label probe`, multiplier 0.25), only when the short probe is borderline. Plus a cheat trial (`--cheat --label cheat`, multiplier 0.1). The coordinator runs them (one trial per runner at a time). A low probe is confirmed only once L3 shows the verifier sound; if steps 4-5 change the scoring, the short probe runs again. Thresholds live in pipeline/config.json `probe_ladder`; results feed back to the judges (data/calibration.json). | recall below 0.3; short probe below 0.15 (go to the full trial) or 0.15-0.35 and a quarter probe below 0.5. A short probe of 0.35 or more, or a recall of 0.3 or more, puts the frontier above the band: that is not a failure under the spec's review gate, so run the second-model gap check (step 7c; a weaker stand-in such as GPT-4.1 via terminus-2, label `weak25`, hints at it before Qwen access); widen and repeat 2-3b only when the weaker model keeps up. Record each trial's output tokens: the long-horizon gate needs some frontier trial to generate substantial work. Cheat reward exactly 0 |
| 4 | Reference in solution/: the strongest that exists, preferably upstream or expert work (the real implementation, an upstream faster release, published results). Expected outputs always come from a real external oracle (upstream code, a standard's conformance suite, real data), never from a behaviour model we wrote: a grader whose answers are our own choices fails grounding (spec line 8) and puts the ceiling exactly where the authoring model already is. Optimization and research: a reference our agents write cannot set the target; use the expert one, and the spec's stretch target S above it where that helps (line 51). Record in notes.txt who authored the reference and the expected outputs. **Strength, with great effort** (spec lines 13, 333, 351: the strongest solution you can build, one the frontier does not reach): this phase runs as a fresh Opus agent at an effort the coordinator judges from the work: medium when the reference is upstream code (most implementation tasks: copying and checking), high only when we author or tune it ourselves (an optimization reference pushed past upstream, a research method we train, a port with no upstream code in the target language). Strength comes from choosing the right expert source, not from effort settings. Implementation: the reference passes every hidden case, and an alternative solution confirms the cases accept any valid implementation. Optimization: start from the best expert work that exists (upstream's fastest release, vendor kernels), measure S on the runner with the robust timing, then try to push past it; set S at the best measured speedup, or above it as a stretch target while the reference still scores at least 0.5 (line 51). Research: the best published method on the task's data, run end to end before its number is claimed (line 55), with the remaining budget spent on improving it | oracle reaches the ceiling; notes.txt names the reference's and the oracle's authors, the effort spent and, for optimization and research, how S or the metric was pushed |
| 5 | L3 (§5), including a `partial-core-*` variant: the narrow solution core.json describes | summary all PASS; partial-core scores within 0.1 of core_share |
| 6 | instruction.md (700-3350 words) and PROVENANCE.md (≥ 80 words); /humanize-writing, then `python3 -I scripts/humanize_diff.py before after` | L0 PASS; the user approves the text |
| 7 | L4 on a runner (§6): one full-budget trial, only after 3b passed | normalized score in 0.05-0.85, ideally a pass (0.9) in some trial; cheat trial scores 0 |
| 7b | **Rework or decide**: a trial outside its target (probe 0.5 or more, full above 0.85, cheat above 0) starts one rework round: widen or harden, then repeat from 2. At most 2 rounds (`max_rework_rounds` in pipeline/config.json); a third miss, or a recorded `build/decision.json` of `{"decision": "failed", "reason": "..."}`, ends the bundle as failed and its slot goes to the next idea. | every bundle ends as passed (ready, full trial in band, cheat 0) or failed with a reason |
| 7a | **Trial order, cheapest evidence first** (`cgpipe.py ladder` runs it): frontier short probe; above the band, one Qwen run at the full budget with the timer armed (`qwen_runs` 1: once the frontier has solved, a second Qwen run cannot change the gap verdict, since 1 of 2 still leaves Qwen at half and 20 points behind); the GPT stand-in only when no Qwen access exists), and a short probe at 0.9 or more counts as the frontier solve the gap needs, so no full frontier trial on that route; in the band, one full-budget frontier trial; the cheat trial last, once the bundle is complete and the gate is met, capped at 1 hour. The requirements' own cheat check is line 26 ("a deliberate cheater scores 0"), which the L3 near-miss variants cover; the agent cheat trial rehearses the platform's adversarial probe (line 331) | each trial runs only when its answer can change the decision |
| 7c | **Second-model gap (the spec's review gate)**: a task reaches review if the frontier's full-budget mean is in 0.05-0.85, **or** it shows a capability gap against Qwen. A frontier result above the band is therefore not a failure: run Qwen trials with Harbor's `qwen-coder` agent, `bash scripts/remote_run.sh run <task> --keys qwen --label qwen -- -a qwen-coder -m openai/<qwen-coder model> -k 1 -n 1 --allow-agent-host <provider host>` (the runner's ~/cg.env holds OPENAI_API_KEY and OPENAI_BASE_URL). Implementation: gap = Qwen solves (0.9) at most half its runs, the frontier solves at least once and its solve rate leads by 20 points; Qwen solving more than half (from 4 runs, `qwen_min_runs`) fails the task as too easy. Performance and research: the frontier improves at least once and its mean leads Qwen's by 0.20. A frontier that finishes with little sustained work is still flagged as a long-horizon risk for the reviewer. | in band, or a gap against Qwen; cheat 0 |
| 7d | **Strengthen the reference from the probe** (optimization and research): a frontier trial at or near 1.0 means the reference is not near the best achievable (spec line 351). Before the gap check, raise the reference (more kernels, a better method, more tuning) or set S above it as a stretch target (line 51), refreeze, rerun L3 and the short probe. Implementation references are already the ceiling (upstream behaviour), so there the scope, not the reference, decides | the frontier's probe stays below the reference |
| 8 | Premortem: a judge subagent reads the bundle against capture/instructions.md "What the pipeline checks" and names the three likeliest rejections; fix or rebut each. It also checks DeepSWE's four review dimensions: the grader tests what instruction.md asks, no more and no less; any reasonable implementation passes; the change is realistic; failures come from the work, not the environment | written in README.md |
| 9 | `bash scripts/make_zip.sh <task>` | the user submits |

## 4. L0: static checks
`~/.local/bin/uv run --no-project --python 3.12 python -I scripts/l0_check.py <task>`. It checks the spec's structure rules:
- required files, task.toml policy (name, paradigm, compute, budget tier, TASK_BUDGET_SECS, limits, no docker_image, no interpolation, no loader variables)
- timer.sh byte-equal to the spec, the Dockerfile tail verbatim, a pinned debian-family base, Claude Code installed, ends as root, no timer autostart
- instruction length and the /app/.timer pointer, PROVENANCE length
- solution size, no archives, solve.sh not touching /tests or /logs/verifier
- nothing graded under environment/
- verifier hygiene (no kill by name, no reward literals in shell, PATH reset, loader variables unset)
- sandbox warnings (Landlock, kill-process seccomp, valgrind, execute-only files, message queues, perf counters, nproc)
- deny-list phrases (scripts/leak-denylist.txt) and leftover TODO/REPLACE markers.
The report goes to tasks/<task>/build/l0-report.md.

## 5. L3: Docker checks (no model, no keys)
`bash scripts/l3_run.sh <task> [--local] [--only oracle,nop,variants,det] [--det-n 50]`. It runs on VM 3 unless `--local`, through remote_run.sh (leak guard first).

| # | Check | Pass rule |
|---|---|---|
| 1 | Build succeeds (every oracle trial builds) | every trial produces a reward |
| 2 | Reference reaches its ceiling, twice (`-a oracle -k 2 -n 1`) | every trial ≥ `oracle_reward_threshold` (default 1) and trials within 0.05 |
| 3 | Untouched state (`-a nop`) | exactly 0 with valid = 1 |
| 4 | near-miss-* | 0, for the intended reason (read details.json) |
| 5 | partial-* | strictly between 0 and the ceiling |
| 6 | alt-solution-* | reaches the ceiling |
| 7 | edge-inside-* / edge-outside-* | inside reaches the ceiling, outside fails that case |
| 8 | Verifier determinism: solve.sh once, test.sh N times at 1 and `cpus` CPUs | one verdict across all runs |

Near-misses that always apply: a native-code or system-tool shortcut, output in the wrong format, a tampered input, a leftover background process, a write to /logs/verifier. Partial: the reference with whole features stubbed out. Output: tasks/<task>/runs/l3-<stamp>/summary.md; wall times go to data/l3-runs.tsv.

## 6. L4: model trials on VM 3
`bash scripts/remote_run.sh run <task> --keys claude -- -a claude-code -m <model> -k 1 -n 1 --allow-agent-host api.anthropic.com` (add `--cheat` for the adversarial trial with the public hack prompt). Our tasks set `allow_internet = false`, which Harbor 0.24 enforces with an egress-control sidecar that would also block the agent's model API; `--allow-agent-host` opens only that host for the agent phase (Harbor src/harbor/cli/jobs.py, checked 2026-10-20). Confirm on the first trial that the agent reached the API and the task container still had no other network. Default plan: one full-budget trial plus one cheat trial. A judge subagent reads both trajectories with the task, the verifier output and the reference: was the failure caused by the hard part (strong), the environment (noise), or a fork in the spec? Did the verifier misjudge the run (a false positive or a false negative)? DeepSWE's audit of 735 rollouts found 1.4 % verifier disagreement on its benchmark against 32 % on SWE-bench Pro, so any false verdict is a verifier bug to fix before submitting. Any reward from the cheat trial is a blocker. For a local stand-in of the platform's weaker model, Harbor's `qwen-coder`, `terminus-2` and `openhands` agents take an OpenAI-compatible endpoint.
